# Publishing a release

`VERSION` is the companion app's version. `metadata.json` describes the stable GNOME bridge; **do not bump its version for ordinary app releases**, because doing so asks users to reload their desktop.

1. Update `VERSION` (for example, to `0.1.1`) and document changes in the commit or PR.
2. Run the tests, commit, and push `main`.
3. Tag that commit with the matching version and push the tag:

```sh
git tag -a v0.1.1 -m "Cal Bar v0.1.1"
git push origin v0.1.1
```

The Release workflow runs the unit, downloaded-installer, calendar RSVP, and isolated two-monitor GTK integration tests on Ubuntu 24.04. If they pass, it publishes:

- `cal-bar-vVERSION.tar.gz`: allowlisted Python/GJS app, GNOME bridge, schema, local installer, documentation, and license.
- `install-cal-bar.sh`: browser/curl-friendly installer pinned to this release.
- `SHA256SUMS`: checksums for both assets.

Archives contain no credentials, local settings, logs, Git history, or generated bytecode. Python/GJS assets are architecture-independent; native GTK/GNOME libraries come from the operating system. The archive is deterministic for the same source tree and build epoch.

Tags with a suffix such as `v0.2.0-rc.1` publish as prereleases. Users can install them by passing that exact version to an existing installer. The `latest` URL continues to select a regular release.

## Install and update

Recommended download-and-review flow:

```sh
curl -fSLO https://github.com/romaad/cal-bar/releases/latest/download/install-cal-bar.sh
less install-cal-bar.sh
bash install-cal-bar.sh --install-deps
```

Or, for users who choose to run the installer directly:

```sh
curl -fsSL https://github.com/romaad/cal-bar/releases/latest/download/install-cal-bar.sh | bash -s -- --install-deps
```

Run as your desktop user. `--install-deps` explicitly permits installing Ubuntu dependencies with `sudo apt-get`; omit it when dependencies are already present. The app itself installs without root. The installer downloads the archive and checksum manifest from the same exact release, verifies the archive, extracts only regular files beneath its expected directory, and runs the local installer. Checksums verify download integrity; they are not a separate publisher signature.

The same command updates an existing installation and restarts the companion if it is running. A first install or changed bridge needs one desktop logout/login; ordinary app updates do not. Then enable the bridge if necessary:

```sh
gnome-extensions enable cal-bar@local
```

Current support is GNOME Shell 46, tested on Ubuntu 24.04. The installer rejects other GNOME versions instead of installing an incompatible bridge. Expand `metadata.json` support only after testing that version.

## Build without publishing

```sh
/usr/bin/python3 scripts/build-release.py
(cd dist && sha256sum --check SHA256SUMS)
```

For a manual upload, create the tag first, build the exact tagged tree, and upload the three explicitly named assets. Do not move an existing published tag or replace release assets; publish a new version instead.
